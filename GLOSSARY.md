# Firststone

The vocabulary of the user's working environment: the projects, the repos that hold their code and knowledge, and the constraints each kind of project carries.

## Language

**Personal project**:
A project the user owns alone, free of any external constraint on process, tools or visibility.
_Avoid_: side project, private project

**Work project**:
A project done for a client with colleagues, bound by coordination duties (meetings, alignment with teammates) and by the client's constraints.
_Avoid_: client project, job

**Home Repo**:
The repo where agent sessions start, holding pointers to every repo one group of collaborators works on.
_Avoid_: knowledge repo, project repo, hub

**Personal Home Repo**:
The user's own Home Repo, never shared, pointing only at their personal projects; it holds nothing about work.
_Avoid_: private home, main home

**Team Home Repo**:
The Home Repo of one Work project, shared with the colleagues on it.
_Avoid_: client home, `<project>-knowledge`, knowledge repo

**Meeting note**:
The distilled record of one meeting: its decisions, its actions with an owner, and its open questions.
_Avoid_: minutes, meeting summary

**Transcript**:
The verbatim record of a meeting or a video, kept by whoever recorded it and never shared.
_Avoid_: recording, raw notes

**App repo**:
A repo holding a project's code, where agents make changes; its stack is irrelevant to the environment around it.
_Avoid_: operational repo, code repo
